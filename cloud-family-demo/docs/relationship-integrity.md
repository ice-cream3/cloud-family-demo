# 业务代码维护关联完整性

所有项目建表脚本均不创建外键。主键、唯一索引、普通索引与 CHECK 约束继续保留；原先由外键隐式创建的反向查询索引在新建表中显式声明。已有库删除外键不会删除索引。

## 关联规则

| 关联 | 校验与删除行为 |
| --- | --- |
| 用户 → 用户角色 | 分配前校验用户、角色存在；删除用户显式删除用户角色关联。 |
| 角色 → 用户角色、角色权限、角色菜单 | 删除角色在同一事务清理三类关联；分配前校验目标角色、权限、菜单存在。 |
| 权限 → 角色权限、菜单权限 | 删除权限在同一事务清理两类关联。 |
| 菜单 → 子菜单、角色菜单、菜单权限 | 拒绝删除仍有子菜单或按钮的菜单；叶子菜单删除时清理两类关联；设置上级时校验存在性、禁止自引用及祖先循环。 |
| 字典类型 → 子类型、字典项 | 写入时锁定并校验父类型；有子类型或字典项时禁止删除父类型；类型编码、字典项编码及上级关系创建后不可变。 |
| 商家 → 类型关联、商品 | 商家类型分配和商品写入均锁定商家并校验；删除有商品的商家被拒绝；删除空商家时显式清理类型关联。 |
| 商家类型 → 商家类型关联、商品类型 | 分配/写商品时锁定并校验类型；删除类型前锁定类型并检查引用；有商家或商品引用时禁止删除。 |

权限、角色、用户、菜单的 `findById` 查询使用 `FOR UPDATE`，作为事务内关系写入的公共父记录校验路径。服务层关联写入、父记录删除及关联清理均在 `faCloudTransactionManager` 事务中执行；相关父记录锁将分配与删除串行化，避免先检查、后插入期间父记录被删除。商家与字典延续专用的锁定查询。无事务的详情查询在单条语句结束后释放锁。

业务约束适用于应用服务写入路径。直接执行导入、初始化或修复 SQL 时，应保持父记录先于关联记录写入、先清理关联再删除父记录；完成后执行完整性检查。不要使用关闭外键检查作为业务逻辑的替代方案。

## 已有库迁移

1. 部署并重启更新后的 manager-service。partner-service 保留已有的商家/类型锁定和有效性检查。
2. 保存现有外键定义，以便需要时恢复。
3. 对每个项目业务库分别执行（脚本仅允许 `fa-cloud`、`fa-model` 及其 `-test` 库，不改动其他库）：

```bash
mysql --database=fa-cloud -p < common-service/src/main/resources/db/remove-schema-foreign-keys.sql
mysql --database=fa-model -p < common-service/src/main/resources/db/remove-schema-foreign-keys.sql
```

脚本按当前库实际元数据移除全部外键，可重复执行。DDL 隐式提交，不自动删除记录、不删除主键或索引。脚本临时创建并移除迁移过程，需要相应过程和 ALTER 权限。

4. 对 fa-cloud 或对应测试库执行 `manager-service/src/main/resources/db/fa-cloud/relationship-integrity-audit.sql`，15 组关联的 `orphan_count` 都应为 0；脚本只读，不自动删除孤立记录。
